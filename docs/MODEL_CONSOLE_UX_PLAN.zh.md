# Model Console 优化方案

状态：设计方案及原始问题记录。P0 / P1 界面与保存改版已部署至本机 DSH；实际验收及限制见 VERIFICATION.zh.md。
检查日期：2026-10-03。

## 目标与边界

Model Console 成为 DSH 中统一的模型管理入口：让用户知道通过什么来源调用模型、常用模型有哪些、哪个是新会话默认模型，以及设置是否保存。会话输入框也使用同一份展示规则，避免管理页简洁而会话选择器仍有几十条。

AG Account Pool 继续负责账号认证、额度、跨账号/模型接力、网络代理和请求记录。Model Console 负责连接这个服务、选择模型和查看调用情况，不再实现一套账号路由。AGY 是客户端；这里的接入名称应是“AG Account Pool API”，不能误称为另一套 Claude CLI。

## 已确认的问题

1. 当前运行时有 6 个接入来源、72 个原始模型条目：DeepSeek 3、Codex 本机登录 7、Claude Code 本机登录 4、Qwen 2、本机 AG Pool 28、188 AG Pool 28。这不是 72 种独立模型，也不代表全部有额度。
2. AG Pool 的相同目录被两个来源重复展示，Gemini 的 low/medium/high 等条目直接出现在长下拉菜单中。用户难以区别模型、推理档位和调用来源。
3. 保存按钮存在，但在当前窗口中被裁切。浏览器宽 1251px；设置内容面板宽 564px，默认模型卡片宽 488px，三列实际占用 190px + 250px + 42.28px，再加间距和内边距。按钮从 x=956.5 开始，卡片在 x=959.5 结束，并设置 overflow:hidden，绝大部分按钮不可见。720px 的媒体查询依据浏览器宽度，未触发面板内部换行。
4. 默认选择不是自动保存；修改后需要点击“设为默认”。实测选择 Sonnet 后点击“刷新状态”，未保存选择被重置回 Gemini 3.8 Flash High，没有提示。
5. 当前设置服务可写，已存默认为 ag-pool / gemini-3.8-flash-high。此次只核查和复现草稿丢失，未改变实际默认值，也不能据此断言持久化接口坏了。
6. 默认模型保存没有暴露 settings 可写状态、版本冲突或完整的 reasoningEffort；保存期间选择器仍可编辑，刷新响应会覆盖后续选择。底层 saveSelection 在没有 settings 服务时可不写入，插件不能仅因 Promise 完成就宣称保存成功。
7. Model Console 的连接卡片只为 Codex 和 Qwen提供完整交互；Claude、DeepSeek、两端 AG Pool 只在底部列出名称和计数。
8. 样式混入固定深色背景，当前浅色 DSH 中出现整块黑色区域。还使用影响外部导航的全局 nav:has 规则。
9. 刷新模型目录、检查 Codex 登录和读取 Qwen 凭据状态绑在一次刷新中，单项失败会影响整个面板。连接状态也缺少“已配置 / 已注册 / 最近实测通过 / 暂不可用”的区分。
10. Qwen 的区域初值固定为中国，没有从已保存地址投影；已有路由的验证会使用原 provider 配置，可能验证旧地址而保存新地址。设置先写、凭据后写也存在部分成功的情况。
11. 已安装 dsh-codex-claude-cli，且 codex-local、claude-local 均 active。llm.providers 返回这两项的 settingsNs 为空；原生“模型”页只把可关联配置命名空间的来源标为 configured，所以不显示它们的编辑卡片。这是集成/配置登记缺口，不是模型不支持。
12. 当前“设置 → 插件 → 插件配置 → Codex App Server”只提供图像生成、Web Search 接管、搜索默认模型和最大结果数。Claude 的 executable、cwd、timeout、permissionMode、retry 等虽在 Host composition Config 中存在，却没有可写用户设置命名空间或前端表单。Model Console 当前也只列表，不提供 Claude 配置。CLI Runtimes 扩展页面只列出两个来源并嵌入 Codex 能力卡片，不能算 Claude 配置已完成。

## 信息结构

保留一个 Model Console 入口，中文副标题“模型管理”，内部使用三个页签。

### 模型目录

- 默认展示“常用”，提供来源选择、搜索、收藏和“全部模型”。
- 来源、模型、推理档位分成三个独立选择；明确标明本机或远程。
- 相同逻辑模型在每个来源中只显示一行。选择 AG Pool 本机后，默认显示目前已接入目录中的 Opus、Sonnet、Gemini 3.8 Flash、Gemini 3.1 Pro、GPT-OSS 120B 五个核心模型。
- Flash 的低/中/高档位在行内或详情中选择，最终仍提交现有的精确模型 ID。Pro 只提供目录中真实存在的档位。tiered、agent、未知别名保留在高级列表，不能仅靠正则当作思考档位。
- 旧版本放入“全部模型”，不删除路由或账号权限。当前会话模型、当前默认模型和用户收藏始终可见，即便已不在推荐名单内。
- 推荐清单以已加载的真实目录为前提，可更新；不能按字符串排序猜哪个是最新，也不凭空出现上游未支持的模型。Codex 子系列不能仅按版本合并。
- 计数分别显示“接入方式”“接入来源”“原始条目”“当前常用模型”。API 来源相同的逻辑模型不重复计入同一视图的模型数；CLI 的别名若不能确认实际型号则保留其来源归属。

### 接入来源

分成三类：

| 接入方式 | 当前来源 | 管理重点 |
| --- | --- | --- |
| 本机登录 | Codex、Claude Code | 安装/登录状态、实际目录、测试 |
| 直接 API | DeepSeek、Qwen | 地址、凭据配置状态、目录、测试 |
| 账号池 API | AG Pool 本机、AG Pool 188 | 地址、机器标识、凭据状态、调用追踪、跳转 Pool |

每个来源提供相同的“详情 / 编辑 / 刷新目录 / 测试”布局；按能力显示操作。Base URL、来源类型和所在机器直接可见；凭据只显示“已配置”及引用标识，已存密钥不回显。

Codex 与 Claude Code 必须各有独立的来源卡片。Claude 卡片显示可执行路径、安装版本、登录状态、模型目录来源（实时探测或回退别名）、最近测试、工作目录与基本超时/重试设置；高级配置保留权限/环境来源。登录仍由原生 Claude Code 维护，不要求填写 API Key。看到 default/opus/sonnet/haiku 四个别名不能自动宣称登录成功，因为目录探测失败也会返回这些别名。

Claude 可编辑参数需要在 dsh-codex-claude-cli 中增加受支持的用户设置命名空间、验证和安全重建进程/目录缓存机制，再由 Model Console 展示统一入口；不能在前端虚构保存能力。Codex 能力配置仍调用其已有 settings namespace，必要时保留插件页跳转。原生 Claude CLI 与 AG Pool 中的 Claude 模型应明确标注不同来源/额度，不共用登录状态或默认路由。

“注册成功”不等于“连通”，目录发现不等于真实生成成功。所有来源初始显示可信的独立状态；测试结果按来源、模型、档位、配置版本记录，并显示时间。单项失败不拖垮其余来源。测试不会创建聊天会话。

原生“模型”页中的通用配置能力通过“高级配置”入口继续可达。先通过受支持的 composition/slot 统一入口，不能通过全局 CSS 隐藏现有页面来假装完成。

### 默认设置

一眼看见“已保存默认值”和“待保存选择”。字段分为来源、模型、推理档位，操作区在内容面板底部可见，窄面板自动换行。

推荐默认采用明确的“保存默认设置”按钮，旁边提供“取消修改”，显示状态：已保存 → 未保存 → 保存中 → 已保存或保存失败。不能同时使用隐式自动保存和含义不清的保存按钮。

如后续选择自动保存模式，也必须显示“保存中 / 已保存 / 失败重试”，并解决异步请求乱序；本期以显式保存降低误切默认模型的概率。

行为规范：

1. 编辑只修改草稿；刷新目录/连接状态不重置草稿。
2. 点击保存，提交完整选择和预期 revision；保存期间禁用相关提交或使用请求版本，避免旧响应覆盖新选择。
3. 服务端校验来源已注册、精确 ID 存在、档位支持、设置可写。
4. 使用 DSH 设置服务持久化；写入后读回比较。只有确认读回一致才显示“已保存”，并给出保存时间。
5. 失败保留草稿，显示原因及重试；只读显示原因，不能静默成功；版本冲突提示配置已被其他页面修改。
6. 关闭页面有未保存修改时提供“继续编辑 / 放弃修改”。
7. 保存仅作用于以后新建的会话；现有会话要显式“应用到当前会话”。Agent 预设显式指定模型时，应显示该覆盖关系。
8. 关闭重开、刷新浏览器、重启服务和真正新建 Session 都要验收持久化与继承，而非只看提示文字。

## AG Pool 接入后的额外信息

- 本机地址与域名地址都是调用同一实例的入口，展示机器身份；188 是另一个实例，模型名相同也不能隐去来源。
- 配置沿用 DSH Credentials 和 llm-pi-ai/provider 服务，账号 OAuth 留在 Pool / Vault。
- 刷新目录不覆盖用户收藏或推荐隐藏规则，不自动迁移既有会话到另一机器。
- 会话中分别展示“请求模型”和“实际执行模型”。自动接力时显示一条说明，例如“Claude Sonnet → Gemini Flash，原因：额度耗尽”，提供匹配请求记录入口。账号只显示脱敏标识。
- 真实模型以 API 返回的 model / X-AG-Pool-Model 为准；请求记录以 X-AG-Pool-Request-Id 关联，不让模型自己回答“我是谁”作为证据。
- 当前 DSH/Pi 适配器尚未把 Pool 的全部响应头作为 UI 元数据暴露。展示账号/接力细节前需补齐受支持的 provider 事件或元数据接口，不能只添加假的前端状态。
- 额度需要 Pool 提供授权范围内的只读状态接口，或明确跳转管理页。GET /v1/models 只提供模型目录，不能由条目数推算剩余百分比；不能向插件安装 Pool/Vault 管理密钥。
- 同一 Session/turn 的绑定若要贯穿普通多轮对话，需在 provider 请求上下文中发送稳定的会话/turn 标识；当前仅有工具调用 ID 续接绑定不能冒称全会话绑定已实现。缺乏受支持的请求扩展点时，做一个薄的 AG Pool provider 集成，仍复用既有路由。

## 技术拆分与开发顺序

1. P0：修正面板尺寸适配、主题和保存状态；服务端增加可写/读回/冲突检查；保留 reasoningEffort，修复草稿覆盖。
2. P1：统一目录投影（模型/来源/档位）、常用/收藏/全部、来源管理卡片；补齐 dsh-codex-claude-cli 的 Claude 设置与状态接口，并把同一目录投影用于会话选择器。
3. P2：AG Pool 只读状态与调用元数据，真实接力提示/请求记录跳转；补齐 Qwen 编辑初始化与设置/凭据部分失败恢复。

建议独立模块：catalog projection、provider projection、draft/persistence controller；ModelConsoleSection 拆成目录、来源、默认设置三个组件。Host RPC 提供脱敏状态和保存结果；不在浏览器直接访问 Google、Pool 管理凭据或本机认证文件。

通过已存在的 settings.section、conversation.input.model 和 modelDirectories/session.selectModel 接缝集成；具体接缝是否支持无冲突替换需在实施时验收。不能直接修改已安装 node_modules 或绕过官方设置存储。

## 验收条件

- 设置内容宽 320 / 564 / 736 / 1040px、浅色/深色均没有裁切，保存/错误提示和键盘操作完整可达。
- AG 两个来源常用视图各为五个核心模型；同一模型的档位不会占据多行；全部列表仍能找到旧 ID。
- 搜索、收藏、来源筛选和会话选择器遵守同一规则；已有 Session 和未知默认模型不会消失。
- 默认保存经浏览器刷新、服务重启和新建 Session 验证；已有会话不被修改；选完刷新状态不丢草稿。
- 保存失败、只读、版本冲突、并行编辑都有正确状态和重试，没有虚假成功。
- 两端 AG Pool 的文本/工具调用成功，实际账号和模型与 Pool 路由记录一致；自动接力用受控 429 验证，并明确标注为模拟。
- API Key 不回显；登录/目录/测试/额度状态彼此独立；未取得授权额度数据时显示未知。
